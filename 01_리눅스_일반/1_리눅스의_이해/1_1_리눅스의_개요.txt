1. 리눅스의 특징
    1-1. 오픈 소스 운영체제
    1-2. 멀티 유저(다중 사용자), 멀티 태스킹(다중 작업) 운영체제
    1-3. 다중 스레드를 지원하는 네트워크 운영체제
    1-4. 여러 종류의 파일 시스템을 지원하는 운영체제
    1-5. 처음에는 어셈블리어로 작성되었고 후에 C언어로 작성


2. 장단점
    2-1. POSIX 표준을 준수하여 유닉스와 높은 수준의 호환성을 가집니다.
        => POSIX는 유닉스 OS에 기반을 두고 있는 표준 운영체제 인터페이스입니다.
        => 리눅스는 POSIX 표준화를 기반하기 떄문에 유닉스 소스코드를 전혀 사용하지 않고 개발되었습니다.
        => 유닉스용 프로그램은 별도의 수정 없이 리눅스에서 동작할 수 있습니다.
    
    2-2. PC용 OS보다 안정적입니다.
        => 리눅스는 네트워크 사용을 전제로 설계되었기에 특별한 사항을 제외하고 항상 켜 놓아도 안정적으로 운영됩니다.

    2-3. 하드웨어 기능을 효과적으로 사용할 수 있습니다.
        => 다른 OS보다 적은 양의 메모리를 필요로 합니다. / Linux OS 자체가 동작하는데 필요한 시스템 자원이 비교적 적다는 것을 의미합니다.
        => SWAP 방식을 통해 RAM이 부족한 경우 SWAP 영역을 늘려 메모리의 효율성을 높일 수 있습니다. / 주기억장치 <-> 보조기억장치(swap 영역)
    
    2-4. 오픈 소스 운양체제

    2-5. 공개 운영체제의 특성에서 비롯된 기슬 지원의 어려움
        => RHEL, SUSE 유료 제공 -> 기술 지원
        => 대부분은 예상치 못한 오류 발생 시 개발자들의 기술 지원 직접적으로 받는 것 힘듬
    
    2-6. 한글 지원의 미흡

    2-7. 보안상 취약점의 노출 가능성
        => 공개 OS이기에 보안에 취약할 것이라는 선입관 -> 꾸준한 기술 개발로 비교적 높은 보안성 지원


3. Linux 디렉터리의 개념
    => 리눅스 디렉터리는 최상위 디렉터리(/)를 기준으로 하위 디렉터리들이 존재하는 계층적 트리 구조로 구성되어 있습니다.
    => 디렉터리 간에는 부모와 자식 관계를 가집니다.


4. Linux 디렉터리별 저장 내용
    4-1. /
        => 파일 시스템이 있는 최상위 디렉터리 / 모든 디렉터리의 출발점인 동시에 다른 시스템과의 연결점이 되는 디렉터리입니다.
    
    4-2. /boot
        => 부트 디렉터리로 커널 이미지와 부팅 정보 파일 저장하고 있습니다.
        => 커널 이미지 : 커널이 실제 파일 형태로 저장되어 있습니다.
        => 부팅 할 떄 부트로더가 /boot의 커널 이미지를 찾고 실행합니다.
    
    4-3. /proc
        => 시스템 정보 디렉터리이며 커널 기능을 제어하는 역할입니다.
        => 현재 실행되는 프로세스와 실제로 사용되는 장치, 하드웨어 정보를 저장합니다.
        => ** 커널의 상태/ 프로세스/ 시스템 정보를 파일처럼 보여주는 가상 파일 시스템입니다.**
        => ** Linux 커널이 현재 가지고 있는 정보를 파일이라는 인터페이스를 통해 보여주는 공간입니다. **
    
    4-4. /lib
        => 공유 라이브러리 디렉터리입니다.
        => Linux가 동작하거나 Linux 내 프로그램이 실행할 떄 필요한 라이브러리가 존재합니다.
        => 또한 커널 모듈 같은 파일들이 존재합니다.
        => 커널 모듈 -> 실행 중인 Linux 커널에 기능을 추가할 수 있는 코드입니다.
        => 하드웨어 드라이버가 커널 모듈 형태로 제공되어 필요할 떄 커널에 로드할 수 있습니다.
        => 정적 라이브러리 : 프로그램 내에서 라이브러리 루틴(코드 덩어리 -> printf..)의 복사본을 갖고 컴파일합니다.
        => 동적 라이브러리 : 실행 파일 내부에 라이브러리 루틴을 넣지 않고 프로그램 실행할 때 주소를 매핑합니다.
    
    4-5. /bin
        => 기본적인 명령어가 저장된 디렉터리입니다.
        => root 사용자와 일반 사용자가 함께 사용할 수 있는 명령어 디렉터리입니다.
        => 터미널에서 사용하는 명령어 -> 프로그램입니다.
        => ls -> shell에서 ls라는 프로그램 실행 -> ls 프로그램 접근 -> 실행
        => ** 즉, /bin에는 기본 명령어라는 실행 프로그램들을 모아놓은 공간입니다. **
    
    4-6. /dev
        => 시스템 디바이스 파일들을 저장하는 디렉터리입니다. -> 장치 파일은 장치 드라이버를 의미합니다.
        => 하드디스크 장치 파일, CD-ROM 장치파일 같은 파일 저장..
    
    4-7. /etc
        => 시스템 환경 설정 파일 저장 디렉터리입니다.
        => ** 즉, Linux 시스템과 각종 프로그램의 설정값을 저장하는 곳입니다. **
        => /etc/hostname -> 컴퓨터의 호스트 이름을 설정하는 파일
        => /etc/group -> 그룹 정보 파일 | /etc/passwd -> 자원을 사용할 수 있는 사용자 목록 파일
        => /etc/shadow -> 패스워드 만기일, 계정 만기일 설정 파일

    4-8. /root
        => 시스템 관리자용 홈 디렉터리입니다. / 루트 사용자의 관련 파일들을 저장합니다
    
    4-9. /sbin
        => 시스템을 관리하기 위한 명령어(실행 파일)이 저장되는 곳입니다.
        => /sbin/reboot, /sbin/mount..
    
    4-10. /usr
        => 사용자 디렉터리로 사용자 데이터나 애플리케이션을 저장하는 곳입니다.
        => Linux에서 사용하는 프로그램-라이브러리-문서 등이 들어가는 곳입니다.
        => 사용자 별로 /usr이 있는게 아니라 /usr이 하나 존재하고 여러 사용자가 함께 사용합니다.
        => /usr/bin -> gcc, python..
        => 현대 리눅스에서는 /bin -> /usr/bin, /lib -> /usr/lib 처럼 연결되어 있습니다.
    
    4-11. /home
        => 사용자 계정 디렉터리로 계정들의 홈 디렉터리 위치입니다. -> 사용자들의 개인 공간
        => 일반 사용자들이 로그인 시 처음으로 위치하게 되는 디렉터리입니다.

    4-12. /var
        => 가변 자료 저장 디렉터리로 로그 파일이나 메일 데이터를 저장하는 곳입니다.
        => 시스템이 실행되는 동안 계속 생성·변경되는 데이터를 저장하는 디렉터리입니다.
        => logs, cache는 실행 중에 지속적으로 만들어지고 변경되는 데이터입니다.
    
    4-14. /tmp
        => 각종 프로그램이나 프로세스 작업을 할 떄 임시로 생성되는 파일을 저장하는 곳입니다.
        => /tmp는 재부팅할 떄 삭제될 수도 있고 일정 시간이 지나면 정리될 수 있습니다.
        => 모든 사용자에 대해서 읽기와 쓰기가 허용됩니다.
        => 스티키 비트 설정으로 파일 소유자만이 삭제할 수 있게 할 수 있습니다.
    
    4-15. /mnt
        => 파일 시스템을 일시적으로 마운트할 떄 사용하는 디렉터리입니다.
    
    4-16. /lost+found
        => 결함이 있는 파일에 대한 정보가 저장되는 디렉터리입니다.
        => 파일 시스템의 이상 유무를 진단하고 fsck에 의해서 사용되는 디렉터리입니다.
        => 손상된 파일이나 디렉터리를 /lost+fount 디렉터리로 연결한 뒤에 오류를 수정하게 되며 
            평상시에는 null 파일 링크에 의해서 비어 있는 상태로 존재합니다.


5. 리눅스 배포판의 개념과 특징
    5-1. 리눅스 배포판은 리눅스 전체 시스템을 구성하는 소프트웨어 패키지 형태입니다.
    5-2. 리눅스 커널, GNU 소프트웨어 및 여러 가지 자유 소프트웨어로 구성된 OS 입니다.
        => 리눅스 커널 != 리눅스 배포판
        => 커널의 존재만으로 웹 브라우저 실행, 파일 관리 X -> 다양한 프로그램을 추가해야 합니다.
        => 리눅스 커널 + GNU 도구 + 패키지 관리자 + 각종 라이브러리.. -> 묶어서 내놓은 것을 리눅스 배포판이라 합니다.
        => GNU 소프트웨어 : OS를 구성하는 여러 자유 소프트웨어를 만든 프로젝트 (bash, gcc, ls/cp/cat..)
        => x-window : Linux에서 GUI 환경을 제공하는 프로그램입니다.

    5-3. 전 세계에 300 가지 배포판, 배포판을 구성하는 소프트웨어 자유롭게 구성되어 있습니다.
    5-4. 용량에 맞춰서 X 윈도우를 뺴거나 용량이 적은 GNU를 선택하기도 합니다.
    5-5. 대표적인 배포판은 슬략웨어, 데비안, 레드햇..


6. 리눅스 배포판의 종류
    6-1. 독립형 배포판
        1. 슬랙웨어 리눅스 (Slackware Linux)
            => 배포판 가운데 가장 먼저 대중화된 1992 패트릭 볼커딩에 의해 출시되었습니다.
            => 패키지 관리 문제 -> 인기 떨어진 상태
            => 구조 간결 -> 유닉스 학습에 리눅스를 사용하고 싶어하는 사용자들에게 적합
    
    6-2. 데비안 계열
        1. 데비안 (Debian)
            => 1994 이안 머독
            => 공개 OS, GNU의 공식적인 후원을 받고 있는 유일한 배포판
            => 정식판 : GNU/리눅스
            => 패키지 설치 및 업그레이드 과정 단순, apt 등을 이용하면 소프트웨어 설치, 업데이트에서 의존성 확인, 보안 관련 업데이트 자동
        
        2. 우분투 (Ubuntu)
            => 데비안 GNU/리눅스에 기초한 OS입니다.
            => 고유한 데스크탑 환경인 유니티를 사용하는 리눅스 배포판입니다.
            => 영국에 기반을 둔 회사인 캐노니컬의 지원을 받고 있습니다.
            => 6달 마다 새 버전 / GNOME의 새 버전이 나오는 시기와 비슷합니다.
            => 사용자 편의성에 초점
    
    6-3. 레드햇 계열
        1. 레드햇
            => 미국의 레드햇사가 개발하던 리눅스 배포판
        
        2. RHEL (Red Hat Enterprise Linux)
            => 레드햇이 개발하여 판매하고 있는 상용 리눅스 배포판입니다.
            => 18 ~ 24개월에 한 번씩 새로운 버전 공개, 라이선스 별도 판매 x
            => 기술 지원은 버전마다 출시 시점으로부터 7년 동안 제공합니다.
            => 서브 스크립션 형태로 요금 지불 / 계약기간 중에는 추가 비용 없이 업그레이드, 다운그레이드 가능
            => 상업용 패키지는 구입 / 소스코드는 레드햇의 FTP 사이트를 통해 공개됨
        
        3. 페도라
            => 리눅스 커널에 기반한 OS + 레드햇의 후원 + 개발 공동체의 지원 아래 개발된 배포판입니다.
            => RPM 기반의 소프트웨어가 결합된 OS
            => 6개월 간격을 새로운 버전 배포, 지원기간은 버전마다 13개월
            => 소프트웨어 개발이 안정적으로 이루어지기 위해서는 새 버전으로 계속 교체되어야 한다는 문제점
        
        4. CentOS와 CentOS Stream
            => 업스트림 소스인 레드햇 엔터프라이즈 리눅스와 완벽하게 호환되는 무료 기업용 컴퓨팅 OS
            => 자체 커뮤티티에 의해 관리
            => CentOS Linux 가장 마지막 버전 7은 2024/07/30 지원 시마이
            => RedHat 정책 변경에 따라 2022부터 CentOS Stream OS로 변경
            => CentOS Stream은 RHEL의 베타버전
        
        5. Rocky Linux
            => CentOS 개발자 그레고리 커쳐 -> CentOS 제작 중단 발표 반발해 Rocky Linux 만들었습니다.
            => RHEL 9 == Rocky Linux 9 동일한 기능
        
    
    6-4. 수세 계열
        1. 수세 (SUSE)
            => 독일에서 출시된 배포판입니다. (유렵에서 인기)
            => 풍부한 기능과 안정성, 보안 기능 포함
            => 정기적인 배포판 x, 언제든지 새로운 버전이 출시되면 업데이트 가능한 롤링 릴리즈 방식 사용합니다.
            => 오픈 수세, 수세 엔터프라이즈 리눅스로 나뉩니다.
