1. 파티션
    
    1-1. 파티션의 개념
        => 파티션은 하나의 물리적 디스크를 여러 개의 논리적인 디스크로 분할하는 것입니다.
    
    1-2. 다중 파티션의 장점
        1. 파티션마다 독립적인 파일 시스템이 운영도기 떄문에 파일점검 시간이 줄어들어 부팅시간 단축시킬 수 있습니다.
        2. 특정 파티션의 파일 시스템이 손상 -> 다른 파티션 영향 x -> 높은 안정성 보장합니다.
        3. 필요한 파티션만 포맷할 수 있기 때문에 백업과 업그레이드가 편리합니다.
        4. 파티션 상태 정보를 확인할 수 있는 파일은 /proc/partitions입니다.
    
    1-3. 파티션의 종류
        1. 주 파티션
            => 부팅이 가능한 기본 파티션입니다.
            => 하나의 하드디스크에 최대 4개의 주 파티션 분할이 가능합니다.
            => 하드디스크를 4개 이상의 파티션으로 사용해야 할 떄 하나의 확장 파티션을 설정하여 확장하고
                확장 파티션 안에 여러 개의 논리 파티션을 분할하여 데이터를 저장합니다.
            => 마지막 파티션이 확장 파티션이 되며 논리 파티션들을 담는 컨테이너가 됩니다.

        2. 확장 파티션
            => 주 파티션 내에 생성하고 하나의 물리적 디스크에 1개만 생성합니다.
            => 파티션 번호는 1~4번이 할당됩니다.
            => 데이터 저장 영역을 위한 것이 아니라 논리 파티션을 생성합니다.

        3. 논리 파티션
            => 확장 파티션 안에 생성되는 파티션입니다.
            => 논리 파티션은 12개 이상 생성하지 않는 것을 권고하며 5번 이후의 번호가 붙여집니다.

        4. 스왑 파티션
            => 하드디스크의 일부를 메모리처럼 사용하는 영역입니다.
            => 주 파티션 또는 논리 파티션에 생성합니다.
            => 프로그램 실행 시 부족한 메모리 용량을 하드디스크로 대신합니다.
            => 리눅스 설치 시에 반드시 설치되어야 하는 영역입니다.
            => 스왑 영역의 크기는 메모리의 2배를 설정하도록 권고합니다.


2. 디스크와 장치명

    2-1. 특징
        1. 리눅스는 하드디스크 자체에도 이름을 붙이고 파티션에도 이름을 붙입니다.
            => /dev/hda -> 하드디스크 하나의 이름입니다. (/dev/hdb, /dev/hdc -> 하드디스크 자체가 2개가 존재)
            => /dev/hda1, /dev/hda2, /dev/hda3.. -> 그 하드디스크의 파티션 이름입니다.
            => /dev/hda3 : hd는 하드디스크, a는 첫 번쨰 디스크, 3은 3번째 파티션
        2. 분할된 파티션은 디스크의 장치 파일명 뒤에 숫자를 붙입니다.
            => /dev/hda3
        3. 리눅스에서 파티션을 만들고 마운트할 떄 지정된 디바이스명을 사용합니다.
        4. hd : IDE 또는 ATA 방식 디스크 / sd : SCSI 또는 USB 방식 디스크

        5. 디스크 데이터 저장 단위
            => 비트 -> 바이트 -> 킬로바이트 -> 메가바이트 -> 기가바이트 -> 테라바이트 -> 페타바이트 -> 엑사바이트 -> 제타바이트 -> 요타바이트


3. 파일 시스템

    3-1. 파일 시스템의 개념과 특징
        1. 파일 시스템은 OS가 파일을 시스템의 디스크 파티션상에 구성하는 방식입니다.
        2. 일정한 규칙을 가지고 파일을 저장하도록 규칙 방식을 제시합니다.
        3. 파티션에 파일 시스템이 없으면, 파일 시스템 방식을 거쳐야 사용이 가능합니다.
    
    3-2. LVM (Logical Volume Manager)
        => 여러 개의 하드디스크를 합쳐서 사용하는 기술로 한 개의 파일 시스템을 사용합니다.
        => 서버를 운영하면서 대용량의 별도 저장 공간이 필요할 때 활용합니다.
        => 다수의 디스크를 묶어서 사용함으로써 파티션의 크기를 줄이거나 늘릴 수 있습니다.
        => 물리 불륨 -> 여러 개의 물리적 하드디스크(sda, sdb..) / 볼륨 그룹 -> 물리 볼륨을 합쳐서 하나의 물리적 그룹으로 만든 것
            논리 볼륨 -> 볼륨 그룹을 나눠서 다수의 논리 그룹으로 나눈 것


4. 고급 디스크 구성과 파티션 관리

    4-1. RAID의 개념과 특징
        => 여러 개의 물리적 디스크를 하나의 논리적 디스크로 인식하여 작동하게 하는 기술입니다.
        => 여러 개의 하드디스크에 일부 중복된 데이터를 나눠서 저장하는 기술입니다.
    
    4-2. RAID 종류
        => 하드웨어 RAID : 하드웨어 제조업체에서 여러 개의 하드디스크를 장비로 만들어 그 자체를 공급
        => 소프트웨어 RAID : 고가의 하드웨어 RAID 대안, OS에서 지원하는 방식을
    
    4-3. RAID와 레벨
        1. RAID 0 : 스트라이핑 저장 방식 (연속된 데이터를 여러 디스크에 나눠 저장, 하나의 디스크 고장나면 전체 시스템 사용 불가)
        2. RAID 1 : 미러링 방식 (하나의 디스크에 데이터를 저장하면 다른 디스크에 동일한 내용이 백업, 공간 효율성 떨어짐)
        3. RAID 2 : 스트라이핑 저장 방식, 기록용 디스크와 데이터 복구용 디스크를 별도로 제공
        4. RAID 3 : 스트라이핑 저장 방식, 패리티 방식 사용 -> 패리티 정보 저장하기 위해 전용 디스크 사용
        5. RAID 4 : RAID 3과 유사한 방식, Block 단위로 저장
        6. RAID 5 : 스트라이핑 저장 방식, 디스크마다 패리티 정보 가짐, 섹터 단위로 저장
        7. RAID 6 : RAID 5 확장 방식
    
    4-4. 파티션 분할
        1. fdisk의 개념과 기능
            => 파티션 테이블을 관리하는 명령어입니다.
            => 디스크 파티션을 생성, 수정, 삭제할 수 잇는 일종의 유틸리티입니다.
        
        2. fdisk 명령어
            => a : 부팅 파티션 지정
            => l : 파티션 종류 선택 시 리눅스에서 지원하는 파티션 목록 확인
            => n : 새로운 파티션 추가
            => t : 파티션 종류 변경
            => w : 파티션 정보 저장
            => p : 파티션 정보 확인
            => q : 작업 종료

5. 예상 문제

    5-1. 다음 중 스왑 파티션에 대한 설명으로 틀린 것은? 4
        1. 리눅스에서 반드시 설치해야 한다.
        2. 리눅스에서는 전통적으로 RAM 용량의 2배를 권장한다.
        3. 가상 메모리 역할을 담당하는 영역이다.
        4. 스왑 파티션의 ID 번호는 8e이다.
            => swap 파티션의 ID 번호는 82 / LVM은 8e / RAID는 fd입니다.
    
    5-2. 다음 중 리눅스를 정상 설치했을 경우 기본적으로 생성되는 파일 시스템으로 틀린 것은? 3
        1. Proc 파일 시스템
        2. Swap 파일 시스템
        3. RamDrive 파일 시스템
            => RAM의 공간 일부를 보조 저장 공간으로 사용하는 소프트웨어 또는 장치입니다.
            => 기본적으로 생성되지 않습니다.
        4. 하나 이상의 Ext3 파일 시스템

    5-3. 다음 중 E-IDE 타입의 디스크를 Secondary Slave에 연결했을 경우에 인식하는 장치 파일명으로 알맞은 것은? 4
        1. /dev/hda
        2. /dev/hdb
        3. /dev/hdc
        4. /dev/hdd
    => 과거에는 IDE 방식으로 하드디스크를 연결했습니다. IDE 케이블 하나에 최대 2개의 장치를 연결할 수 있습니다.
    => 그리고 두 장치의 역할을 Master, Slave로 구분했습니다.
    => IDE 연결 단자에 두 개 -> primay IDE, Secondary IDE
                     Master        Slave
                    ─────────     ─────────
        Primary       hda            hdb
        Secondary     hdc            hdd
