* 라이선스 * 
    => 프로그램을 만든 사람이 다른 사람에게 이 프로그램을 어떻게 사용해도 되는가를 정해놓은 사용 규칙입니다.
    => 프로그램을 배포하면서 몇몇 조건을 지키면 자유롭게 사용해도 된다고 정해놓인 것이 소프트웨어 라이선스입니다.


1. 자유 소프트웨어 운동과 GNU 프로젝트 
    1-1. GNU (GNU's Not Uxin)
        => 리처드 스톨만이 FSF에서 진행하며 유지 중인 OS 프로젝트
        => 1983년 GNU 개발 처음 시작
        => 유닉스 계열 컴퓨터 OS로 완전한 유닉스 호환 소프트웨어 시스템이 되는 것이 목표입니다.

    1-2. FSF
        => 1985 리처드 스톨만이 설립한 재단
        => 자유 소프트웨어는 사용자가 소트트웨어를 실행, 복제, 배포, 학습, 개작, 행상시킬 수 있는 소프트웨어
        => 자유는 금전적인 측면과 관계가 없기 떄문에 자유 소프트웨어를 유로로 판매할 떄 문제가 생기지 않습니다.

    1-3. Open Source Software
        => 1998년 일부 커뮤니티에서 자유 소프트웨어 대신 오픈 소스 소프트웨어라는 용어를 사용하기 시작했습니다.
        => 자유가 가진 무료라는 의미가 일으키는 혼동을 피하기 위함입니다.


2. 자유 소프트웨어 라이선스의 발전 (GPL 계열)
    2-1. GNU GPL (General Public License)
        => GPL은 FSF에서 만든 Free 소프트웨어 라이선스입니다.
        => 1989, 1991, 2007 -> 3차 버전까지 발표
        => 어떤 프로그램을 개발할 떄 GPL 코드 사용한 경우 -> GPL 적용 대상이 되지만 예외 라이선스가 있을 수 있습니다.
        => GPL을 가진 프로그램은 유료로 판매 가능 but, 전체 소스코드는 무료로 공개해야 합니다.
        => GPL 코드를 사용한 소프트웨어를 내부적인 목적으로만 사용할 떄에는 소스코드 공개 안해도 되지만 외부로 공표-배포할 떄는 공개해야 합니다.
    
    2-2. GNU LGPL (Lesser General Public License)
        => GPL보다 훨씬 완화된 조건의 공개 소프트웨어 라이선스입니다.
        => LGPL이 적용된 라이브러리를 이용하여 개발했을 경우 프로그램 소스코드는 공개하지 않아도 됩니다.
        => LGPL 코드를 사용했음을 명시만 하면 됩니다.
        => LGPL 코드를 단순히 이용하는 것이 아니라 이를 수정한 또는 이로부터 파생된 라이브러리를 개발하여 배포하는 경우 -> 전체 소스코드 공개해야 합니다.


3. 오픈소스 라이선스의 다양화
    3-1. BSD(Berkeley Software Distribute) 라이선스
        => 버클리 캘리포니아 대학의 자유 소프트웨어 저작권의 한 가지입니다.
        => 소스 코드 공개의 의무가 없고 상용 소프트웨어에서도 무제한 사용 가능한 라이선스입니다.
        => 해당 소프트웨어는 아무나 개작할 수 있고, 수정한 것을 제한 없이 배포할 수 있습니다.
        => 수정본의 재배포는 의무적인 사항이 아니기에 상용 소프트웨어에서도 사용가능
    
    3-2. 아피치 라이선스 (Apache)
        => 아피치 소프트웨어 재단에서 자체적으로 만든 라이선스 규정입니다.
        => 아피치 2.0 라이선스는 해당 소프트웨어에서 파생된 프로그램 제작할 수 있고 저작권을 양도-전송할 수 있는 라이선스 규정입니다.
        => 누구든 자유롭게 아피치 소프트웨어를 다운받아 전체/부분을 개인적 혹은 상업적 목적으로 이용할 수 있습니다.
        => 재배포 시 원본 소스코드 또는 수정한 소스코드를 반드시 포함시켜야 하는 것은 아니지만
            아피치 라이선스 버전 2.0을 포함시켜야 하며, 아피치 소프트웨어 재단에서 개발된 소프트웨어라는 것을 명확하게 밝혀야 합니다.
    
    3-3. MIT(Massachusetts Insititue of Technology) 라이선스
        => 미국 메사추세츠 공과 대학에서 개발한 허가서입니다.
        => BSD 라이선스를 기초로 작성된 BSD 계열 라이선스 중 하나입니다.
        => 해당 소프트웨어는 누구나 개작할 수 있고, 수정본 재배포 시 소스코드 비공개가 가능합니다.
        => 이 라이선스가 적용된 소프트웨어는 X Window System, JQuerym Node.JS
        => 소프트웨어를 개조한 제품을 반드시 오픈 소스로 배포해야 한다는 규정이 없고 GNU 일반 공중 허가서의 엄격함 피하려는 사용자들에게 인기
        => 카피 레프트가 아니며, 오픈 소스 여부에 관계없이 재사용을 인정하고 있습니다.
        => MIT 허가서를 따르는 대표적 소프트웨어로 X 윈도우 시스템이 있습니다.
    
    3-4. MPL (Mozilla Public License)
        => 오픈 소스와 자유 소프트웨어 라이선스입니다.
        => 1.0판은 넷스케이프 커뮤니케이션 코퍼레이션의 변호사인 미첼 베이커의 의해 작성, 1.1판은 모질라 재단이 작성했습니다.
        => MPL은 변형 BSD 사용 라이선스와 GNU 일반 공중 사용 라이선스의 혼합적 성격을 띠고 있습니다.
        => MPL의 특징은 소스코드와 실행파일의 저작권을 분리했다는 점입니다.
        => 수정한 2차 소스코드는 MPL로 공개하고 원저작자에게 수정한 부분에 대해 알려야 하지만, 실행 파일은 독점 라이선스로 배포할 수 있습니다.
        => 사용한 MPL 소프트웨어와 수정한 MPL 소프트웨어에 대한 공개 의무만 가지며, 별도의 소스코드와 실행 파일은 독점 라이선스를 가질 수 있습니다.


시험 문제
    1. 다음 중 라이선스 특성이 다른 것은?
        1. 아피치
        2. MIT
        3. BSD
        4. MPL
    => 정답은 4번
    => MPL은 아피치, MIT, BSD 라이선스가 적용된 프로그램들의 소스코드를 수정해서 사용할 경우에도
         반드시 별도의 소스코드와 실행 파일을 공개할 필요는 없습니다.
